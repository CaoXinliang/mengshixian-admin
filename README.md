# 梦食鲜运营管理后台

这是与用户商城前端分离的运营后台。所有写操作调用真实 CloudBase API，不在浏览器中伪造商品、价格、库存、订单、退款、营销或账务状态。

普通员工默认进入 `simple.html` 商家后台，通过固定左侧九个入口完成日常工作：今日待办、订单处理、商品管理、库存管理、退款售后、客户管理、配送设置、营销活动、系统设置。`index.html?mode=advanced` 只承载分类、配送区域编码、内容、权限和操作记录等低频高级设置；二者复用同一登录会话和 CloudBase API，不是两套业务系统。

## 启动前条件

1. `backend/cloudbase/functions/api` 已部署到测试环境 `cloud1-d8gp843lt5454ada7`。
2. 首位超级管理员已经通过本地安全脚本创建；初始化令牌不得重新写入 `config.js`、网页或 Git 记录。
3. 静态托管本目录时保留 `config.js`，环境 ID 可以公开，但管理员口令、初始化令牌、支付密钥和云端密钥绝不能写入网页代码。

## 当前能力

- 商品与价格支持单条维护、批量提交、逐行结果和失败项重试；AI 或临时数据只能作为草稿，不能直接正式启用。
- 库存支持按仓库查看、入库出库和流水筛选；订单支持服务端筛选、详情快照、追加备注、批量履约、脱敏导出和脱敏拣货单。履约明文联系方式只能在二次确认后按单读取并留下审计。
- 售后工作台不允许人工伪造退款成功；套餐、拼团实例/成员、优惠券及领取核销、积分/会员、评价、发票、储值测试记录、企业账期/对账和询价报价都在现有九个一级入口的二级区域内维护。
- 角色权限可视化、操作记录以及商品、价格、内容和营销配置的服务端版本历史统一放在系统设置。回退会由历史快照生成新修订，不覆盖原历史。
- 上传到云存储后，素材会以 `media_assets` 记录保存来源、临时标记、版本和文件 ID；替换素材不需要改商城 UI 代码。
- 登录页会先调用 `health` 检查 CloudBase 连通性；显示“服务连接正常”后仍登录失败时，应优先核对管理员账号、密码和会话状态，而不是重复修改 Web 安全域名。
- 当前目录已发布到测试环境 `/admin-test/`；后台与微信小程序都调用同一套 CloudBase API，但静态托管发布和小程序体验版上传仍是两个独立发布动作。

## 安全与发布边界

- 订单导出与拣货单默认仅含脱敏履约信息；不得把明文联系方式混入批量文件。
- 发票服务商、储值充值、真实支付与真实退款通道未配置时，页面必须显示未配置或待人工处理，不得显示已完成。
- 单个模块权限不足、网络失败或超时不会清除管理员会话；只有明确的会话过期或未登录错误才会清理会话并返回登录页。
- 本地代码完成不代表已部署。发布静态后台、部署云函数和写入 CloudBase 数据必须分别执行并验证。

仓库不包含云端环境变量值、管理员密码或本机 DPAPI 凭据。
