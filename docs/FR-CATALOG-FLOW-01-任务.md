# FR-CATALOG-FLOW-01：交付Excel到商品发布的本地连续验收

来源：用户已明确要求使用交付文件实际导入，验证“上传表格→草稿→上传关联素材→补价格→核对→上架→顾客身份可见”；不得以分散页面模拟通过代替闭环。

当前缺口：交付两份XLSX已浏览器解析；实际API已用程序化行跑通商品/图片/价格/库存/报价，但两者未用同一数据和跨页面连通。复用现有导入、素材、商品核对模块，不重做。

分步推进：
1. 使用交付空白模板与项目来源演示表，经真实浏览器解析后调用实际本地API预览/保存草稿；确认选择文件无写入、空白拒绝、逐行原因、重复重试不多建、没有自动上架。
2. 沿同一导入商品在页面补分类、真实测试PNG及视频关联、明确本地测试价格库存、配送，核对缺项与发布保护。价格库存只存在内存，不冒充甲方真实数据。
3. 同一本地应用读取个人/企业可见性、规格、价格和媒体；验证报价/配送。小程序前端只读核对，真实云上传与实际小程序需要另外授权，不突破禁止部署/线上写入。

测试接缝采用用户要求的文件→后台界面→实际API，复用已验证的隔离Edge绑定机制。外部数据库/存储可用替身，不能mock商品业务成功回应。每步留具体运行证据及未覆盖边界，按需修正发现的问题。

约束：蓝色多页面、每文件≤800行；只友方后台与必要API，保护未提交改动和原回退点；不提交推送部署，个人线与小程序不改。营销、复杂企业采购仍暂缓；批量素材匹配维持下一阶段，不用不可用模板冒充。
