# 暂缓模块与后续开发路径

## 当前决定（2026-09-23）

- 企业采购范围已按用户最新决定调整：本轮实施简化企业下单与线下实际收款登记，复用购物车、规格、配送、订单；支持未收款、部分收款、已收齐，履约与收款分开。具体当前任务以 `OPERATIONS-USABILITY-PLAN.md` 顶部为准。
- 仍暂缓：询价、单独报价、复杂账期、授信、跨订单应收核销；企业价是否与个人价相同未定，不合并价格规则、不编造价格。保留企业资料和历史订单。
- 营销模块暂缓：本轮不扩展拼团，不新增通用优惠活动、优惠券、积分、积分商城、优惠叠加及预约生效规则。已有拼团代码保留；不创建或启用线上活动。
- 本文件是后续工作记录，不代表已实现或已获得后续开发/部署授权。恢复时先核对真实代码及用户最新范围。

## 复杂企业采购的未来路径（不属于本轮简化收款）

1. 确认企业采购业务范围、岗位权限及价格适用规则，再恢复企业专属价/询价；身份审核和价格资格分开。
2. 账期与授信独立建模，明确额度、逾期、冻结与负责人审批；不能把企业审核通过当成获准赊账。
3. 应收、实际收款、分配核销和退款分别记账；交付状态与收款状态分开。
4. 验收真实收款凭证、重复处理、撤销与对账，再申请测试环境及发布授权。

现有定位：`backend/cloudbase/functions/api/lib/admin-operations-actions.js` 的客户身份/企业审核及价格动作；`lib/pricing-targets.js`；`pricing.html`、`users.html`、`businesses.html`。这些现有入口不等于完整企业采购系统。

## 营销恢复路径

| 顺序 | 工作包 | 前置规则和交付 |
| --- | --- | --- |
| 1 | 冻结正常价格和优惠计算规则 | 确认适用客户、优惠先后、是否叠加、互斥时如何选择、分摊/舍入、退款返还；未决定前不默认某种规则 |
| 2 | 通用优惠活动 | 新建独立多页面模块；名称选商品/客户范围，时间与名额，先草稿；模拟购物车展示原价、优惠和最终金额，再明确发布 |
| 3 | 优惠券 | 模板、发放/领取限制、用户持有券、订单锁定/核销、取消释放、退款返还、到期与流水；并发与重试不可重复领取或核销 |
| 4 | 积分账本 | 每次增加/扣减/退回均有原因和来源单据；订单完成后按规则发放，重复回调幂等 |
| 5 | 积分兑换商品 | 兑换品、积分价、独立库存、限额、有效期；积分与库存一致扣减，失败恢复 |
| 6 | 可选：积分抵订单金额 | 与兑换商品分开开关；必须另行确认开启、比例、上限和叠加规则，不能默认开放 |
| 7 | 统一结算与版本生效 | 服务端计算价格→按已确认顺序应用优惠→运费；保存订单优惠分摊快照；预约版本仅影响生效后的新订单 |
| 8 | 后台模拟购买和验收 | 客户身份、券/积分/库存足不足、开始前结束后、重复提交、取消与退款；每项可说明为何可用或不可用 |

现有技术入口：

- `groups.html` 与 `backend/cloudbase/functions/api/lib/groups.js`：已有拼团专用功能，仅作现状参考，不能冒充通用优惠引擎。
- `backend/cloudbase/functions/api/lib/commerce.js`：当前服务端报价、订单创建和库存规则，后续统一优惠必须进入这一结算链路。
- `lib/customer-order-actions.js`、`lib/refunds.js`：订单/支付/退款入口及状态规则，后续接券和积分的锁定、核销、返还；审核通过不能代替支付/退款渠道结果。
- `lib/permissions.js`、后台 `access.html`、`audit.html`：权限和审计；重大活动发布、关键价格修改需按岗位授权。
- `admin-page-registry.js`：新增营销页面时登记独立路由；模块超过 800 行前拆分，不堆回总入口。

建议未来模块按优惠规则、券生命周期、积分账本、积分兑换、结算分摊分别拆分；恢复时再编写当期规格和测试，不预造无法运行的模板或菜单。
