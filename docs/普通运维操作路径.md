# 友方后台普通运维操作路径

以下是已实现入口和验收边界，不是允许向线上导入、上传或发布的通知。2026-09-24 的测试服部署与小范围云验证已有记录（见 `FR-CLOUD-DEPLOY-01-测试服验收.md`），但不是正式上线，也不表示本文每一步都在云端和实际小程序跑通。当前页面可能连接友方真实云环境；需要试操作时，由开发人员先确认隔离测试环境，不要直接拿演示资料操作线上后台。

## 本机练习入口（只用于隔离演示）

打开 `http://127.0.0.1:8766/login.html`，认准页面顶部“本机练习环境”提示，再点“一键进入本机练习后台”。资料保存在这台电脑的独立练习区，不写友方云端、也不会出现在真实小程序。这个一键入口会取得本机超级管理员权限，仅供本人练习；不要给甲方当作多人共用的正式后台，也不要填真实客户资料、价格或库存。若页面无法打开，需要开发人员在友方后台工作区运行 `node local-preview/start.cjs` 启动服务，不要求普通运维人员操作命令行。

原来的友方云端账号和密码不能直接登录这个独立的本机练习后台。查看操作记录时，从“高级管理 → 系统管理 → 操作记录”进入；按时间从近到远看中文事项、对象名称与操作人。“当前角色”是该工作人员现在的角色，不保证等于当时的角色；看不到的旧对象会明确标记。内部编号默认收起，仅供排查。本机已验证超管可读、运营账号被服务端拒绝，友方云端页面仍未部署此改动。

隔离 Edge 已用交付 XLSX 实际完成“预览六行 → 确认仅存草稿 → 选一条生成商品草稿 → 上传 PNG/WebM 并按名称关联 → 补合成个人价/库存/配送 → 核对并明确发布 → 本机顾客接口可见 → 退出后重新登录”。缺项和取消时不会上架；素材名称搜索、普通运营账号的获准操作与越权拒绝也已在本机页面实测。所有价格、库存、区域、手机号与短片均为合成测试资料。这不证明友方云端新接口、真实小程序展示或真实下单已经验收；原友方测试网址仍只有页面更新，不能直接照此练习线上业务。

## 首次营业前先检查

登录后从“工作台 → 开店检查”进入，逐项看仓库、配送区域、配送时段、运费、库存、商品价格；缺项可点“去补齐”，有记录的项目点“去核对”。页面只检查基础记录是否存在，不证明仓库与区域匹配、价格和配送报价正确，更不证明顾客已可下单。收款状态固定显示“尚未核验”；读取失败会显示“暂不可用”，不要据此判断配置不存在。本地浏览器已分别验证缺项、读取失败和同一笔本地商品链的接口数据；友方云环境、真实收款与小程序可下单仍未验收。此页不启用店铺，也不写入业务数据。

## 按顺序准备商品

| 步骤 | 打开哪里 | 你要做什么 | 本地证据与限制 |
| --- | --- | --- | --- |
| 1. 整理表格 | 商品导入 `imports.html` | 下载 Excel，填写名称、分类、规格、包装；一个规格一行。没有业务编码时使用后台辅助生成或选择，不填数据库编号 | 已使用交付空白表、演示表测试解析；当前模板仅导入六列基础资料，价格、库存、产地和素材不由此表导入 |
| 2. 预览并保存草稿 | 商品导入 | 看逐行错误和重复提示，修正后重新选文件，最后确认保存草稿 | 交付XLSX经浏览器与实际本地API保存6条草稿、取消与重复导入已验证，不自动上架；重新建立编码关系时禁止保存旧结果，已本地浏览器实测 |
| 3. 配图片和视频 | 素材库 `media.html` → 商品核对发布 `product-review.html`；分类图片在 `categories.html` | 从电脑选择文件、登记素材，再在商品核对页选择用途和对应规格；主图关联整个商品。分类图片可按素材名称选择，不填素材 ID。已上传素材只改名称、来源或适用端时点“改资料”；换文件才点“新建版本”。若提示“资料已被其他人修改”，刷新列表、重新核对后再保存，不覆盖别人的新内容。商品“专业资料”若提示原主图暂不可用，会保留原关联；先核对素材库，不要误以为没有主图 | 本地 PNG、WebM 表单及预览失败/恢复已验证；“改资料”已用本地实际接口验证不重传、不换版本、保留日志，并验证旧弹窗被拒与日志失败回滚。素材列表读取失败时原主图保留已用隔离浏览器验证。测试服仅记录一枚小图片真实云上传。**当前日常入口仍限 24 MB**；24–100 MB 视频直传代码仅本地测试、默认关闭，不能让运营拿真实文件操作。真实云存储、CORS、事务并发和超时未验收 |
| 4. 补价格与库存 | 商品编辑 `product-workflow.html`／价格管理 `pricing.html`；库存 `inventory.html` | 按元填写已确认价格；按名称选择价格适用顾客、规格和仓库，价格列表也显示适用对象名称；按实际补货登记库存，不猜数字。若库存保存提示回执不明，先核对当前库存；保持同一笔内容重试，不能凭猜测再填一次 | 名称选择与价格列表已浏览器验证；本地实际 API 验证补货成功但回执丢失、重新打开后重试不会重复计入；个人小程序价格、库存和仓库启用条件有服务端核对；未验证真实云端结算或事务并发 |
| 5. 配送和上架前核对 | 配送区域 `areas.html`、运费 `freight.html`、时段 `slots.html` → 商品核对发布 | 按名称选区域和仓库；补齐匹配的运费与时段。新区域、时段默认停用，核对后才启用。回到商品核对页逐项检查 | 区域/时段名称选择与取消/保存已用模拟接口实点；商品核对检查存在有货仓库与配送配置组合，不保证任意地址可送达 |
| 6. 明确确认发布 | 商品核对发布 | 图片加载成功、视频试播、缺项全部处理后，再点确认发布；不确定就取消 | 本地浏览器验证取消零提交、确认携带当前核对结果、双击只提交一次、重新读取后显示上架；不是实际云端发布 |

## 之后再做什么

- 商品确认无误后，再进轮播图 `banners.html` 或首页模块 `sections.html`：在“素材”处输入名称查找、选择并点“预览所选素材”，只从已上架商品中选跳转目标；核对页面列出的跳转位置、适用端和生效时间后再启用。保存失败原因会留在当前弹窗内。本页图片已用本地测试文件实测加载；本页视频试播、真实云存储与实际小程序仍未验收。
- 日常改价、补货、下架、处理订单和退款，使用各自页面，不通过商品表格顺便执行。
- 企业申请在 `businesses.html` 点“查看并审核”：先看企业、门店、地址、主营、联系人和两张申请图片（门头照片、营业执照），确认实际内容后勾选核对，再选通过或驳回并二次确认。任何一张图打不开时按钮保持禁用；申请人改过资料会拒绝旧核对并刷新，需重新打开。无需填写文件编号。这里只在本地隔离浏览器用模拟图片验证了页面门槛，真实云端证照能否打开、内容是否真实仍须人工和测试环境验收；不能仅因图片成功显示就认定企业真实合法。
- 退款申请在 `refunds.html` 点“查看并核对”：看原订单号、商品明细、付款状态、原金额、已退金额、剩余可退金额，以及本次申请金额和原因。核对真实收款后勾选，再点通过或驳回并二次确认。列表不再直接批准，也不显示内部订单 ID；金额超额、原订单明细缺失、未支付或运营账号无审核权限时不能提交。申请或原订单已变化时关闭后重新打开核对。审核通过仅显示“退款处理中”，不表示款项已退到顾客；须继续等真实退款结果。本地接口和隔离浏览器已验证，云端退款渠道未验收。
- 工作台读取失败显示“暂不可用”，不能将它理解为没有订单或没有待办。
- 企业线下收款已通过本地同单页面测试：订单中心→线下订单“查看收款”→核实真实到账→填元金额、北京时间、方式和备注→“核对并登记”→确认→查看已收/待收及流水。它只记录收款，不会发起银行扣款，也不改变发货状态。未部署，不要据此在云端登记测试金额；复杂企业采购与营销仍暂缓。

## 仍不能声称已经完成的验收

补充本地证据：交付 XLSX 已经由浏览器跨页接到同一内存资料的实际业务 API，完成草稿、PNG/WebM 上传登记关联、补价格库存配送、核对发布、个人价格读取及结算报价；详见`FR-CATALOG-FLOW-01-本地验收.md`。存储和上传仍为本地测试替身，不是友方云端或小程序验收。

1. 实际测试小程序的页面可见性、规格选择、视频播放与下单前结果，不能用本地顾客 API 代替。
2. 核对过程中新增规则的并发检测，以及真实云事务的容量、性能和冲突处理。
3. 真实云存储上传、长视频完整播放和网络中断恢复。
4. 线上发布及真实业务数据写入仍需单独授权；当前本地通过不自动执行。
5. 真实收款与退款结果不属于“后台保存成功”；未连接或未验收的支付退款能力不能称为可用。

上述云端和小程序验证需要另行获准的隔离测试环境及操作授权。本轮没有提交、推送、部署或写线上业务数据。
