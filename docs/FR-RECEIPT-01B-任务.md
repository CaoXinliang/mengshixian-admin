# FR-RECEIPT-01B：订单内登记收款

依据：已批准的 FR-RECEIPT-01 规格v1及用户逐项采纳的第二步；无需重复确认既定操作流程。唯一状态入口为OPERATIONS-USABILITY-PLAN.md。

入口：订单列表线下订单的“查看收款”；同页独立面板展示订单号、订单总额、累计实收、待收、履约状态和流水。receipts.read控制读取，receipts.write控制登记；服务端始终鉴权。

流程：确认真实到账→按元填金额、北京时间、方式、备注→明确核对确认→保存→重新读取流水与订单。无内部编号输入，不把登记解释为银行扣款或微信收款。

失败保护：历史待核实、取消/关闭、在途退款或已收齐不能新登记；加载失败不显示假零；重复点击只有一笔。网络结果不明保留同一凭据及内容，禁止改内容再以新凭据重记；先核对流水，允许原内容重试。金额沿用admin-money.js，不自行浮点乘100。

架构：独立admin-order-receipts.js/css；主Agent负责app.js/admin-tables.js/orders.html接入及API必要返回字段；子Agent只写独立模块及直接测试，不修改共享文件。每文件小于800行、保留蓝色多页面。

测试接缝：已确认的浏览器界面与API dispatch。先补交互测试，再最少实现，覆盖元金额、日期、取消零请求、两次点击、失败原凭据重试、权限、历史未知、退款限制与成功后刷新；主Agent执行全测、隔离浏览器及独立审查。01C另以同一实际本地API订单连通浏览器全过程。

禁区：不改小程序/个人线、价格规则、旧订单、退款流程；不提交推送部署或写线上业务数据；不改变原回退点。
