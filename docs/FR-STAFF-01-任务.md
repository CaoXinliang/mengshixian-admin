## 两角色权限清单（实施目标，不冒充当前已生效）

超级管理员：工作人员新增/编辑/停用/重设密码/两角色分配，查看角色和审计；本轮已存在的业务管理权限。仍受最后超级管理员保护及服务端发布/退款/收款规则限制，不能绕过资料与金额校验。

运营采用固定最小业务权限，不允许直接附加权限或自建角色：

| 日常职责 | 拟用现有权限点 | 限制 |
| --- | --- | --- |
| 商品/分类/规格、核对上架下架 | catalog.read/write | 上架必须条件完整及明确对象确认 |
| 导入预览、草稿处理 | imports.read/write | 不批量上架 |
| 图片视频上传、版本、关联 | media.read/write | 历史文件不覆盖 |
| 正常商品价格维护 | pricing.read/write | 已确认资料、按元显示、对象核对；不更改企业定价规则 |
| 订单日常处理 | orders.read/write | 履约与付款分开；禁止绕过业务状态校验 |
| 企业线下收款 | receipts.read/write | 核对订单、金额、时间、方式；幂等和操作流水 |
| 实际库存登记 | inventory.read/write | 按实际库存，不编造 |
| 配送配置查看 | delivery.read | 配送启停及规则修改由超级管理员处理 |
| 仓库配置查看 | inventory.read | 仓库新增/修改/停用仅超级管理员；运营仍可登记实际库存 |
| 首页内容维护 | content.read/write | 核对受众/跳转对象；目标需已上架 |
| 售后申请查看 | refunds.read | 退款审批/执行仅超级管理员；不新增真实支付接入 |

运营无admin.read/write、无角色写入、无通配权限、无refunds.write、无营销/复杂企业采购权限；不得改自己角色或任何超级管理员资料。工作人员接口服务端限定超级管理员；自己的密码与账号信息走独立本人接口，不借此修改角色。若实际页面有额外读取依赖，先用拒绝用例定位，再给最小投影/权限，不授予整域管理权限凑通页面。

## 必须通过的验收

- 未登录、运营直调账号/角色接口、修改自己角色或超级管理员、伪造直接权限均拒绝；允许的商品/素材/订单/收款路径可用。
- 退出成功后当前token失效；刷新、后退、重新打开受保护页以及旧token接口重放不能访问；其他会话是否保留按“仅当前会话退出”验证。退出接口失败不能假称服务端注销成功。
- 未验证手机明确显示未验证；客户端传已验证无效；真实验证能力未接通不出现假成功；换号码清除验证。
- 最后一个可用超级管理员不能被停用或降权；同时修改两个超管、停用角色/旧权限路径、账号超过一页等不能绕过；历史账号不删除。
- 发布、退款、收款确认显示对象；审计有操作者、对象、时间、动作和必要结果；收款重复提交不重复计账。退款审批不等于真实退款成功。
- 页面权限、服务端权限分别验收；单文件≤800行；日志和接口不泄露凭据。
